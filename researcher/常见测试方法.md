# 常见测试方法

本项目当前以仓库中的真实测试文件为准。后端测试不调用真实 LLM 时，通过 stub、monkeypatch 或 fixture 隔离外部服务；前端 `package.json` 暂未配置 Vitest 测试脚本。

## 后端测试

在 `deep_research_system/` 目录执行：

```bash
# 全部后端测试
python -m pytest tests/ -v

# 单个测试文件
python -m pytest tests/test_research_api.py -v
python -m pytest tests/test_research_service.py -v
python -m pytest tests/test_graph_topologies.py -v
python -m pytest tests/test_report_validator.py -v
python -m pytest tests/test_topology_router.py -v
python -m pytest tests/test_model_router.py -v
python -m pytest tests/test_key_pool.py -v
python -m pytest tests/test_security.py -v
```

当前测试文件覆盖：

- `test_research_api.py`：使用 `TestClient` 和 stub service 验证 `/api/research` 等路由的响应结构、查询、同步、取消、删除和 SSE 行为。
- `test_research_service.py`：验证任务创建、执行、缓存、失败和取消等生命周期行为。
- `test_graph_topologies.py`：验证 Hierarchical/Debate 拓扑向 graph runner 的委托，不调用真实模型。
- `test_report_validator.py`：验证报告的确定性校验规则。
- `test_topology_router.py`：验证任务类型到拓扑的路由。
- `test_model_router.py`、`test_key_pool.py`：验证模型能力路由、API Key 池和熔断逻辑。
- `test_security.py`：验证安全配置与请求相关行为。

## 外部依赖边界

- 后端测试应优先 mock LLM、搜索服务和 Redis，避免网络调用、费用和不稳定结果。
- API 路由使用真实 FastAPI 应用和 `/api` 前缀；服务层可用 stub 替换。
- 拓扑测试保留真实拓扑入口，但用 stub graph runner 验证委托和状态结果。
- Redis 负责任务状态与事件的持久化；没有 Redis 时只能测试进程内行为，不能验证重启恢复。

## 前端检查

前端当前可用的脚本来自 `deep_research_system/frontend/package.json`：

```bash
cd deep_research_system/frontend
npm ci
npm run dev
npm run build
npm run preview
```

`npm run build` 会先执行 `vue-tsc`，再执行 Vite 构建，可用于类型和生产构建检查。当前没有 `test` 或 `vitest` 脚本，不要将未配置的 Vitest 文件或命令当作现有测试。

多会话相关行为可通过开发服务器手工检查：创建多个任务、切换侧边栏会话，确认各自的 SSE、轮询和 Token 缓冲独立运行，且切换不会停止其他任务。
