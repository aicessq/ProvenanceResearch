# Deep Research 改进实施计划

日期：2026-10-21。目标分支：`dev`。状态：**步骤 1–3 已实施并有离线回归；步骤 4 对照基础设施及离线自检已交付，真实云质量与人工核验待执行；步骤 5 未开始**。实际机制及问题对应见 [agent-mechanisms.md](agent-mechanisms.md)。

依据：[三项目调研](deep-research-comparison.md)、[路线图](roadmap.md)、[测试基线](testing.md)。本轮聚焦 P3d 的证据缺口闭环和 P4 质量改进；不将新文档或离线测试通过当成阶段验收完成。保留工作区已有调研和决策记录，不覆盖用户改动。

## 目标与边界

让研究过程明确回答：缺什么证据、为何选择下一次调用、取得了什么支持、为何停止。改善引用验证失败导致的误拒，保持事实支持与预算要求。

沿用 Evidence v2、Source Registry、ToolExecutor、Reader、Citation Gate、云模型适配器和 SSE v1。生产仍禁止本地权重、mock 证据及缺配置静默降级。本轮不迁入上游框架，不改旧拓扑、知识引擎入库或云供应商，不附带重构。

## 0. 实施前核对与基线

- 核对 roadmap 各前置项的实际证据，尤其 P3a 未完成接线、P3d 验收、P4 未达门槛；不根据状态表中的“完成”概述跳过缺口。影响本次链路的前置缺口先处理，其他缺口如实记录，不据此宣称整个阶段通过。
- 在 Windows 上定位已有 Python 环境，按 testing.md 对应命令运行 agent、providers、evidence、tools、ingest、tests_bridge 与 researcher 回归；必要时再检查 KE 基线。不安装本地模型或下载权重补环境。
- 先记录当前失败及环境限制；测试红了先修复与本轮相关的问题，范围外问题明确列出，不擅自扩展改动。
- 固定实施前提交、代码/prompt/模型/索引版本与离线测试结果。真实云评测沿用有效出站授权；配置指纹变化时按既有授权机制处理。

验收：本轮所依赖的测试可复现，阶段阻塞项及评测前置清晰；未通过则不进入对应实施步骤。

## 1. 修正规划输出与停止判定

主要文件：`agent/loop.py`、`agent/budget.py`、`agent/tests/test_loop.py`、`agent/tests/test_budget_reader.py`。

- 将 planner 输出做结构化校验；坏 JSON、错误字段类型、矛盾完成状态不再转换成“证据充分”。沿用现有错误处理契约，确需新增公开停止原因时先同步接口与测试。
- 明确区分证据充分、轮数/工具/token 耗尽、超时、无进展；保留有证据时在剩余预算内生成的路径，最终结果不得覆盖真实停止原因。
- 检查规划、检索、验证和重生成的预算边界；修复时限与轮数边界所需的最小改动，不顺手改模型层。

验收：合法停止、非法输出、轮数耗尽、工具耗尽、超时、重复无进展均有实际执行测试；不会出现“解析失败/耗尽但标记充分”。已有有据作答和无据拒答保持通过。

## 2. 显式知识缺口与证据更新

主要文件：新增 `agent/gaps.py`，修改 `agent/loop.py`，新增 `agent/tests/test_gaps.py` 并扩展 loop 测试。

- 定义最小缺口状态：gap_id、研究问题、required_scope、证据 ID、已尝试查询、完成条件和 open/resolved/unresolved 状态；先服务单 Agent，不引入任务调度器。
- planner 输入增加来源范围、工具错误、已尝试动作、缺口和剩余预算；所有支持项必须可回查 EvidenceStore，模型不能凭空登记证据。
- 用现有五工具填缺口，记录 gap→call_id→citation_id 关联。优先正文读取和定向补搜；缺口闭合必须结合证据与完成条件验证，不仅接受模型自报。
- 复用既有 plan/tool/evidence 事件承载可展示的结构化进度，不输出内部推理。若需新增字段，保持旧消费者兼容并补事件测试。

验收：仅缺正文时走 fetch/read；缺独立事实时补搜；取得支持后停止；失败或重复结果不误闭合缺口；调用总量不因增加缺口状态扩大。

## 3. 引用验证反馈与受限部分作答

主要文件：`agent/citation_gate.py`、`agent/loop.py`、对应 agent 测试；必要时修改 researcher 的结果映射及其契约测试。

- 给验证失败提供可路由的结构化原因，保留原有登记/scope/数字/语义检查强度。
- 区分缺证据、缺正文和表述越界：前两者反馈到补检索，后者反馈到 writer 收缩结论。所有修复消耗同一任务预算，并保留现有一次重生成上限；不允许 VERIFY→SEARCH→GENERATE 无限循环。
- 对部分有据问题，以通过检查的 claims 重建答案并再次验证正文与 claims 的一致性，同时明确未解决部分；不能只删 claims 而保留无据正文。全部无据仍拒答。
- 优先保留 `answered/refused` 公共状态；如需新增局限性字段，仅作向后兼容扩展，并校验 HTTP/SSE/前端消费者。是否涉及前端文件以契约变更的必要性为准。

验收：部分有据能给出安全的部分回答；未支持数字和视觉结论不泄漏到正文；验证失败能触发恰当修复；预算耗尽/取消及时停止，终态唯一；伪引用和摘要越权仍被拒绝。

## 4. P4 消融与质量重新验收

主要文件：`eval/pipelines.py`、`eval/runner.py`、`eval/metrics.py`、`tests_bridge/test_p4_eval.py`（实施时核对实际路径），以及独立版本的实验配置/报告。

- 保留旧 A/B/C 与 round1.freeze.json，不改历史基线或事后放宽阈值。
- 新实验依次比较：当前单 Agent、显式 gap 单 Agent、gap+验证反馈与部分作答。通过明确开关或固定版本形成可复现消融，不复制三套业务实现。
- 数据、模型/provider、索引、来源、预算和重复次数一致；明确标注各实验的 prompt/代码差异。费用包括规划、检索、修复、验证和生成。
- 先离线验证 runner 和安全样例，再做真实云对照，每条件至少三次；旧金标准 verified=false 的机械分不能独立用于最终质量裁决，人工核验项保留给用户。
- 报告引用准确率、答案质量、误拒/拒答、Recall@k、p95、token/API 费用及未知费用标记；补充重复搜索率、缺口闭合和部分作答覆盖情况。

验收：执行原有安全与质量门槛、明确比较非回归；不达标则记录归因、修复并重跑。未取得真实质量证据前不宣称改进有效，不进入 Supervisor 实施。

## 5. 后续候选：结构化委派与 Supervisor

本项仅列为下一轮候选，不混入前四步。前置步骤及路线图对应阶段验收完成后，再确定范围。

- 借鉴 Skywork 定义子任务输入/权限/完成条件和结构化结果，返回 evidence_ids、未解决缺口、失败与用量。
- 参考 Open Deep Research 对独立子任务做受控并行，保持原始 Evidence/locator；摘要用于导航，不能替代来源。
- 使用全局预算预留/结算和父任务取消，处理分支失败、重复检索及证据合并；禁止每个 Worker 获得一份完整预算。
- 与改进后的单 Agent 在同源同模型同全局预算下比较，再决定是否进入生产路径。

## 提交、文档与验证纪律

按“停止判定→缺口状态→验证反馈→评测”拆成可独立回归的小步提交，全部在 `dev`，不合并 main。每步动手前说明三句话影响面，完成后给文件 diff、理由和实际测试结果；追加 decisions.md，更新 testing.md 的实测记录。阶段状态只在达到验收后更新。

测试以实际变更为准：核心步骤跑目标 agent 测试及相关 bridge；服务/事件变更补 researcher 契约；阶段收尾跑上述六目录和 researcher 全量回归、仓库契约与 diff 检查。仅在修改前端时运行前端构建。真实云调用和离线 fake 测试的结论分开报告。
