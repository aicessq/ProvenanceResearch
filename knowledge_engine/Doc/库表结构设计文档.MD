# CyberSec RAG Agent 数据库结构设计文档

> 本文档是 `文档2.MD` 中数据库部分的独立拆分版，用于在正式编码前冻结库表结构、外键关系、索引策略和关键数据约束。

---

# 1. 设计目标

第一版数据库结构必须满足以下目标：

- 支持文档上传、版本替换、软删除
- 支持 parent-child chunk 存储
- 支持 PostgreSQL FTS 检索字段
- 支持 Qdrant 向量检索所需 payload 元数据回溯
- 支持 query log、用户反馈、攻击性请求审计
- 支持评测数据集、评测运行结果、评测明细持久化
- 支持后续 Alembic migration 平滑扩展

---

# 2. 总体设计原则

- 数据库统一使用 PostgreSQL
- 主键统一使用 UUID
- 第一版优先软删除，不以物理删除为主路径
- 所有业务枚举第一版使用 `VARCHAR + 应用层枚举校验`
- 所有 JSONB 字段必须有明确默认值
- 所有业务关键过滤字段必须建立索引
- 所有时间字段使用数据库时间
- 不允许把 Redis 中的临时状态当成唯一事实来源

# 4. 表结构设计

## 4.1 documents

用于记录一份逻辑文档。

```sql
CREATE TABLE documents (
    id UUID PRIMARY KEY,
    title VARCHAR(512) NOT NULL,
    doc_type VARCHAR(64) NOT NULL,
    source_filename VARCHAR(512) NOT NULL,
    storage_path TEXT NOT NULL,
    current_version_id UUID NULL,
    status VARCHAR(32) NOT NULL DEFAULT 'active',
    security_domain JSONB NOT NULL DEFAULT '[]',
    tags JSONB NOT NULL DEFAULT '[]',
    created_at TIMESTAMP NOT NULL DEFAULT NOW(),
    updated_at TIMESTAMP NOT NULL DEFAULT NOW()
);
```

说明：

- 一条 `documents` 代表一个逻辑文档，不代表单个文件版本
- `current_version_id` 指向当前默认生效版本
- `storage_path` 表示逻辑文档主路径
- `title` 不要求全局唯一

索引：

```sql
CREATE INDEX idx_documents_doc_type ON documents(doc_type);
CREATE INDEX idx_documents_status ON documents(status);
CREATE INDEX idx_documents_created_at ON documents(created_at DESC);
CREATE INDEX idx_documents_current_version_id ON documents(current_version_id);
CREATE INDEX idx_documents_security_domain_gin ON documents USING GIN(security_domain);
CREATE INDEX idx_documents_tags_gin ON documents USING GIN(tags);
```

---

## 4.2 document_versions

用于记录文档版本。

```sql
CREATE TABLE document_versions (
    id UUID PRIMARY KEY,
    document_id UUID NOT NULL REFERENCES documents(id),
    version_no INTEGER NOT NULL,
    file_hash VARCHAR(128) NOT NULL,
    file_size BIGINT NOT NULL,
    mime_type VARCHAR(128) NOT NULL,
    storage_path TEXT NOT NULL,
    version_status VARCHAR(32) NOT NULL DEFAULT 'active',
    publish_date DATE NULL,
    effective_date DATE NULL,
    expire_date DATE NULL,
    change_summary TEXT NULL,
    created_at TIMESTAMP NOT NULL DEFAULT NOW(),
    updated_at TIMESTAMP NOT NULL DEFAULT NOW(),
    UNIQUE(document_id, version_no)
);
```

说明：

- `file_hash` 用于 replace 时判断文件内容是否 unchanged
- `storage_path` 是该 version 对应的实际文件路径
- 同一文档允许保留历史版本

索引：

```sql
CREATE INDEX idx_document_versions_document_id ON document_versions(document_id);
CREATE INDEX idx_document_versions_version_status ON document_versions(version_status);
CREATE INDEX idx_document_versions_effective_date ON document_versions(effective_date);
CREATE INDEX idx_document_versions_publish_date ON document_versions(publish_date);
CREATE INDEX idx_document_versions_file_hash ON document_versions(file_hash);
```

补充：

- `documents.current_version_id -> document_versions.id` 的外键允许在后续 migration 中分步补上

## 4.3 chunks

用于记录 parent / child chunk。

```sql
CREATE TABLE chunks (
    id UUID PRIMARY KEY,
    document_id UUID NOT NULL REFERENCES documents(id),
    version_id UUID NOT NULL REFERENCES document_versions(id),
    parent_chunk_id UUID NULL REFERENCES chunks(id),
    chunk_index INTEGER NOT NULL,
    chunk_type VARCHAR(32) NOT NULL,
    text TEXT NOT NULL,
    normalized_text TEXT NOT NULL,
    chunk_hash VARCHAR(128) NOT NULL,
    doc_type VARCHAR(64) NOT NULL,
    doc_title VARCHAR(512) NOT NULL,
    chapter VARCHAR(512) NULL,
    section VARCHAR(512) NULL,
    article_no VARCHAR(128) NULL,
    page_start INTEGER NULL,
    page_end INTEGER NULL,
    security_domain JSONB NOT NULL DEFAULT '[]',
    keywords JSONB NOT NULL DEFAULT '[]',
    metadata JSONB NOT NULL DEFAULT '{}',
    search_tsv TSVECTOR NULL,
    is_active BOOLEAN NOT NULL DEFAULT TRUE,
    created_at TIMESTAMP NOT NULL DEFAULT NOW(),
    updated_at TIMESTAMP NOT NULL DEFAULT NOW(),
    UNIQUE(version_id, chunk_index)
);
```

说明：

- `normalized_text` 用于生成 `chunk_hash`
- `parent_chunk_id` 用于 child 回取 parent context
- 默认检索仅对 `chunk_type = child AND is_active = true` 生效
- parent chunk 仅存数据库，不写入向量和关键词主索引

索引：

```sql
CREATE INDEX idx_chunks_document_id ON chunks(document_id);
CREATE INDEX idx_chunks_version_id ON chunks(version_id);
CREATE INDEX idx_chunks_doc_type ON chunks(doc_type);
CREATE INDEX idx_chunks_chunk_type ON chunks(chunk_type);
CREATE INDEX idx_chunks_is_active ON chunks(is_active);
CREATE INDEX idx_chunks_chunk_hash ON chunks(chunk_hash);
CREATE INDEX idx_chunks_parent_chunk_id ON chunks(parent_chunk_id);
CREATE INDEX idx_chunks_article_no ON chunks(article_no);
CREATE INDEX idx_chunks_page_start ON chunks(page_start);
CREATE INDEX idx_chunks_page_end ON chunks(page_end);
CREATE INDEX idx_chunks_metadata_gin ON chunks USING GIN(metadata);
CREATE INDEX idx_chunks_security_domain_gin ON chunks USING GIN(security_domain);
CREATE INDEX idx_chunks_keywords_gin ON chunks USING GIN(keywords);
CREATE INDEX idx_chunks_search_tsv ON chunks USING GIN(search_tsv);
```

## 4.4 ingest_tasks

用于记录文档入库、替换、重建索引任务。

```sql
CREATE TABLE ingest_tasks (
    id UUID PRIMARY KEY,
    document_id UUID NOT NULL REFERENCES documents(id),
    version_id UUID NOT NULL REFERENCES document_versions(id),
    task_type VARCHAR(32) NOT NULL,
    status VARCHAR(32) NOT NULL,
    message TEXT NULL,
    error_message TEXT NULL,
    progress INTEGER NOT NULL DEFAULT 0,
    created_at TIMESTAMP NOT NULL DEFAULT NOW(),
    updated_at TIMESTAMP NOT NULL DEFAULT NOW(),
    finished_at TIMESTAMP NULL
);
```

规则：

- `progress` 取值范围 `0-100`
- `failed` 时必须写 `error_message`
- `completed` 或 `failed` 时必须写 `finished_at`

索引：

```sql
CREATE INDEX idx_ingest_tasks_document_id ON ingest_tasks(document_id);
CREATE INDEX idx_ingest_tasks_version_id ON ingest_tasks(version_id);
CREATE INDEX idx_ingest_tasks_status ON ingest_tasks(status);
CREATE INDEX idx_ingest_tasks_task_type ON ingest_tasks(task_type);
CREATE INDEX idx_ingest_tasks_created_at ON ingest_tasks(created_at DESC);
```

## 4.6 feedback

用于记录用户反馈。

```sql
CREATE TABLE feedback (
    id UUID PRIMARY KEY,
    query_log_id UUID NOT NULL REFERENCES query_logs(id),
    score INTEGER NOT NULL,
    comment TEXT NULL,
    created_at TIMESTAMP NOT NULL DEFAULT NOW()
);
```

规则：

- 第一版 `score` 取值范围固定 `1-5`
- 一个 `query_log` 可以有多次反馈

索引：

```sql
CREATE INDEX idx_feedback_query_log_id ON feedback(query_log_id);
CREATE INDEX idx_feedback_score ON feedback(score);
```

# 5. 外键关系

```text
documents
  └── current_version_id -> document_versions.id

document_versions
  └── document_id -> documents.id

chunks
  ├── document_id -> documents.id
  ├── version_id -> document_versions.id
  └── parent_chunk_id -> chunks.id

ingest_tasks
  ├── document_id -> documents.id
  └── version_id -> document_versions.id

feedback
  └── query_log_id -> query_logs.id

eval_dataset_items
  └── dataset_id -> eval_datasets.id

eval_runs
  └── dataset_id -> eval_datasets.id

eval_run_items
  ├── run_id -> eval_runs.id
  └── dataset_item_id -> eval_dataset_items.id
```

删除策略：

- 第一版默认不做级联物理删除
- 默认采用 `ON DELETE RESTRICT` 或框架默认限制策略
- 不允许因为删除文档而清除历史 query_logs 或 eval_runs

# 6. JSONB 字段约束

第一版统一如下：

- `security_domain`: `list[str]`
- `tags`: `list[str]`
- `keywords`: `list[str]`
- `filters`: `dict[str, Any]`
- `retrieved_chunk_ids`: `list[str]`
- `reranked_chunk_ids`: `list[str]`
- `metadata`: `dict[str, Any]`
- `expected_keywords`: `list[str]`
- `expected_chunk_ids`: `list[str]`

要求：

- 默认值必须为 `[]` 或 `{}`
- 第一版禁止混入对象数组和多层嵌套复杂结构
- API 与 schema 层必须做类型校验

# 7. 版本与更新规则

## 7.1 当前版本规则

- `documents.current_version_id` 代表默认检索生效版本
- replace 成功后必须原子更新该字段
- 默认检索只查 current version

## 7.2 unchanged 复用规则

- diff 以 child chunk 为准
- parent chunk 可重建
- unchanged child 在新版本下仍需保留一条新记录
- 新记录复用旧 embedding 与旧索引数据
- 不允许对 unchanged child 重跑 embedding

## 7.3 软删除规则

文档删除时：

```text
documents.status = deleted
chunks.is_active = false
Qdrant payload.is_active = false
关键词索引记录不可见
```

---

# 8. 检索相关库表约束

- 默认检索要求：
  - `documents.status = active`
  - `document_versions.version_status = active`
  - `documents.current_version_id = chunks.version_id`
  - `chunks.is_active = true`
  - `chunks.chunk_type = child`
- `search_tsv` 仅服务 PostgreSQL FTS
- parent chunk 不参与 Qdrant 和 FTS 主检索
