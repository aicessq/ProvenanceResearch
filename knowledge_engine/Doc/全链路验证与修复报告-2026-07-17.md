本次基于提交 `f770e838481d981847d39ddc577affaf7ba5c242`。Python 全部通过 Conda 环境 `rag_sec_phase1` 执行。为避免破坏已有数据，建立了独立 PostgreSQL（55432）、Redis（56379）和 Qdrant（56333）容器；integration fixture 只迁移、清理隔离数据库。

## 2. 实际发现和修复

1. **Alembic 命令路径错误**：`backend/alembic.ini` 在从 `backend/` 执行时仍指向 `backend/alembic`。修正为 `alembic`。
2. **ORM 源码被错误忽略**：`.gitignore` 的 `models/` 同时忽略了 `backend/app/models/`。规则锚定为 `/models/`，使 ORM 包可纳入版本控制。
3. **错误响应不统一**：FastAPI 默认把业务错误包成 `detail.error`。增加全局 HTTPException 转换，业务错误稳定为顶层 `error`。
4. **answer API 注入断裂**：路由测试替换的 retriever 未传入 QueryService。恢复显式依赖注入，同时保留 service 默认构造路径。
5. **测试契约漂移**：worker fake 未接受新增的 embedding fallback 参数；upload 测试把内部 UUID 与 JSON 字符串直接比较。修正测试 seam，不改变正确生产行为。
6. **基础设施测试会 skip**：PostgreSQL/Redis/Qdrant 不可达时原测试跳过。改为严格失败，避免“绿色但未验证”。
7. **容器部署缺少共享上传目录和迁移**：backend/worker 增加同一 `shared_storage` volume；启动前执行 Alembic；模型目录只读挂载；LLM/model/storage 配置显式传递。
8. **前端构建配置不完整**：修正 TypeScript bundler/ES2020 配置并增加 Vite 环境类型声明。
9. **文档域指引严重过时**：`Doc/CLAUDE.md` 不再声称项目未实现，也不再指示读取跟踪的凭据文件。
