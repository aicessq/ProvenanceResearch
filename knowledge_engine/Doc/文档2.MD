# CyberSec RAG Agent Claude Code 可执行规格文档

> 本文档不是泛泛的方案说明，而是给 Claude Code 逐阶段执行的明确实现规格。
> 
> 要求：
> 1. 必须按 Phase 顺序实现；
> 2. 每次只实现当前 Phase 范围；
> 3. 未被当前 Phase 明确要求的功能，不得提前实现；
> 4. 每完成一个 Phase，必须给出修改文件清单、运行命令、测试命令、验收方式；

# 0. 项目目标

实现一个面向网络安全专业知识管理与检索的 RAG 系统，用于管理私有知识资料，并支持结构化检索、引用回答、版本管理和安全防护。

支持的知识类型：

- 网络安全法规 PDF
- 网络安全标准规范 PDF
- 网络安全教材 PDF / 电子书
- Markdown / TXT 笔记
- 后续可扩展漏洞修复知识、应急响应手册、安全制度文档

系统目标不是通用聊天机器人，而是一个具备完整知识入库、检索、引用和更新能力的网络安全 RAG 知识库系统。

# 2. 已确认的默认决策表

以下内容已经明确，Claude Code 必须严格遵守。

## 2.1 版本与上传策略

- `POST /api/v1/documents/upload`：只允许创建新 document，不允许自动挂到已有 document 下。
- `POST /api/v1/documents/{document_id}/replace`：用于创建该 document 的新 version。
- 不允许通过标题自动识别版本归属。
- 不允许在 upload 接口通过 `document_id` 指定挂接旧文档。

## 2.2 知识更新策略

必须采用 **chunk diff 增量更新**：

- 只重新解析被替换的那个 document；
- 只重新切分该 document；
- 通过 `chunk_hash` 比较新旧 chunks；
- 仅对新增 chunk 和内容变更 chunk 重新生成 embedding；
- 未变化 chunk 必须复用旧 embedding 和旧索引数据；
- 不允许因为局部知识修改而重建整个向量库；
- 不允许因为单个 document 更新而全库重算 embedding。

## 2.3 Chunk 索引策略

- **只索引 child chunk**；
- parent chunk 仅用于上下文回填，不进入 Qdrant，不进入关键词索引；
- 检索命中 child 后，可以根据 `parent_chunk_id` 回取 parent 内容用于答案生成。

## 2.4 任务状态策略

必须采用 **数据库 + Redis 双写**：

- Redis 用于实时任务状态；
- 数据库用于任务持久化、审计和接口查询；
- 业务接口以数据库为准，必要时可补充 Redis 中的最新状态；
- 必须新增 `ingest_tasks` 表，不允许把任务状态强行塞进 documents 或 versions 表。

## 2.5 模型接入策略

- Embedding：本地模型
- 大模型：API 调用
- 本地 Embedding 默认模型：**Qwen Embedding 本地部署**
- Reranker：第一版接入**真实 reranker**，默认使用 **本地 Qwen3 Reranker**

## 2.6 Embedding 模型接入方式

第一版采用：

- **Python 进程内直接加载本地 embedding 模型**
- 后端进程直接调用本地模型完成 embedding
- 不采用 OpenAI-compatible embedding API 代理层

同样地，Reranker 也采用：

- Python 进程内直接加载本地 reranker 模型

## 2.7 本地模型目录规则

本地下载模型统一放在项目目录下，例如：

```text
cybersec-rag-agent/
  models/
    embedding/
    reranker/
```

要求：

- `models/` 目录必须加入 `.gitignore`
- 代码中通过配置读取本地模型路径
- 不允许把模型文件提交到 git 仓库

## 2.8 检索默认版本策略

默认检索规则：

- 只检索 `documents.status = active`
- 只检索 `document_versions.version_status = active`
- 只检索当前 document 的 `current_version_id`
- 只检索 `chunks.is_active = true`

若用户明确提问“新旧版本区别”“旧版规定”等，再允许放宽版本过滤。

## 2.9 引用最小粒度

每条回答引用至少必须返回：

- `chunk_id`
- `doc_title`
- `page_start`
- `page_end`

并且：

- 若能识别到 `chapter` / `section` / `article_no`，则必须返回；
- 若没有，则返回 `null`；
- 不允许伪造条款号或章节号。

## 2.10 法规长条款切分规则

对于法规 / 标准 / 制度文本：

- 先按章 / 节 / 条切；
- 当单条内容超过 token 阈值时，再按自然段拆 child chunk；
- 第一版阈值固定为：**800 tokens**；
- 条款编号必须保留在每个子 chunk 中。

## 2.11 当前版本与历史版本规则

必须采用以下版本可见性约束：

- `documents.current_version_id` 指向当前检索默认生效版本；
- 同一个 `document_id` 在任意时刻只允许一个 current version；
- `document_versions.version_status` 表示该版本的业务状态，例如 `active / expired / amended / draft / unknown`；
- `documents.status` 表示逻辑文档是否整体可见，例如 `active / deleted / archived`；
- 检索默认同时受 `documents.status`、`document_versions.version_status`、`documents.current_version_id`、`chunks.is_active` 四重约束；
- 文档替换成功后，必须原子化更新 `documents.current_version_id`。

## 2.12 Chunk Diff 复用规则

当替换文档时，必须遵守以下规则：

- diff 比较对象以 **child chunk** 为准；
- parent chunk 可整体重建，但不得因此触发 unchanged child 重算 embedding；
- `unchanged child chunk` 必须在新版本下保留一条新的数据库记录；
- 该新记录允许复用旧向量与旧关键词索引数据，不重新生成 embedding；
- 新旧版本中 `chunk_index` 不要求稳定一致，不得把 `chunk_index` 作为 diff 主键；
- `chunk_hash` 才是判断内容是否变化的唯一依据；
- 如果仅 parent 内容变化而 child `chunk_hash` 不变，则 child 视为 unchanged。

## 2.13 元数据与 JSON 字段约束

以下 JSONB 字段第一版统一约束：

- `documents.security_domain`: `list[str]`
- `documents.tags`: `list[str]`
- `chunks.security_domain`: `list[str]`
- `chunks.keywords`: `list[str]`
- `chunks.metadata`: `dict[str, Any]`
- `query_logs.filters`: `dict[str, Any]`
- `query_logs.retrieved_chunk_ids`: `list[str]`
- `query_logs.reranked_chunk_ids`: `list[str]`

要求：

- 默认值必须分别为 `[]` 或 `{}`；
- 不允许混入数字数组、对象数组或嵌套多层结构作为第一版输入；
- API 层必须在入参校验阶段保证类型正确。

## 2.14 统一错误响应规则

所有 API 失败返回必须统一为：

  "error": {
    "code": "string",
    "message": "string",
    "details": {}
  }
}
```

第一版至少预留以下错误码：

```text
invalid_request
unsupported_file_type
document_not_found
task_not_found
version_not_found
file_unchanged
conflict
internal_error
```

默认约束：

- `message` 面向最终用户，应简洁可读；
- `details` 仅放结构化补充信息，不放内部堆栈；
- 内部异常必须记日志，但不得直接透出给用户。

## 2.15 检索默认参数与排序规则

第一版固定如下：

- Qdrant distance metric：`Cosine`
- vector search top_k = 30
- keyword search top_k = 30
- RRF 融合参数 `k = 60`
- reranker 输入候选 = 融合后前 20
- 最终 evidence top_k = 5
- PostgreSQL FTS 为主检索，`ILIKE` 仅作为中文召回不足时的补充 fallback
- fallback 命中结果必须并入关键词检索结果，再统一参与 RRF
- 不允许让 `ILIKE` fallback 单独替代 FTS 主流程

## 2.16 文件存储规则

第一版固定采用本地文件存储：

- 上传原始文件统一保存到项目配置的 storage 根目录；
- `documents.storage_path` 存储相对稳定的可回溯路径；
- 替换新版本时保留旧版本原始文件，不覆盖旧文件；
- 文件路径中必须包含 `document_id` 与 `version_id` 或等价唯一标识；
- 不允许仅以原始文件名作为物理文件名。

## 2.17 评测数据持久化策略

第一版评测模块必须持久化以下对象：

- 评测数据集定义；
- 评测数据集中的单条样本；
- 每次评测运行结果；
- 每条样本在某次评测运行中的明细结果。

因此数据库设计中必须补充评测相关表，不允许只保留文件级 `golden_dataset.jsonl` 而没有数据库结构。

  ↓

  ↓

  ↓

  ↓

# 6. 数据库设计

## 6.0 总体设计约束

数据库设计必须遵守以下原则：

- 统一使用 PostgreSQL；
- 主键统一使用 UUID；
- 软删除优先，不做第一版物理删除主路径；
- 所有业务枚举第一版先用 `VARCHAR + 应用层枚举约束` 实现；
- 所有 `created_at` / `updated_at` / `finished_at` 使用数据库时间字段；
- 所有 JSONB 字段必须有明确默认值；
- 所有外键关系必须显式声明；
- 所有检索默认过滤依赖的字段必须建立索引；
- Alembic migration 中必须补充必要索引和唯一约束，不允许只建表不建索引。

## 6.1 documents 表

用于记录一份逻辑文档。

```sql
CREATE TABLE documents (
    id UUID PRIMARY KEY,
    title VARCHAR(512) NOT NULL,
    doc_type VARCHAR(64) NOT NULL,
    source_filename VARCHAR(512) NOT NULL,
    storage_path TEXT NOT NULL,
    current_version_id UUID NULL,
    status VARCHAR(32) NOT NULL DEFAULT 'active',
    security_domain JSONB NOT NULL DEFAULT '[]',
    tags JSONB NOT NULL DEFAULT '[]',
    created_at TIMESTAMP NOT NULL DEFAULT NOW(),
    updated_at TIMESTAMP NOT NULL DEFAULT NOW()
);
```

补充约束：

- `current_version_id` 在 migration 中增加到 `document_versions(id)` 的外键；
- 由于 `documents` 与 `document_versions` 存在循环依赖，允许通过分步 migration 建立外键；
- `storage_path` 存储原始上传文件的主路径；
- 不要求 `title` 全局唯一。

`doc_type` 枚举：

```text
law
regulation
standard
textbook
case
policy
manual
note
other
```

`status` 枚举：

```text
active
deleted
archived
```

索引：

```sql
CREATE INDEX idx_documents_doc_type ON documents(doc_type);
CREATE INDEX idx_documents_status ON documents(status);
CREATE INDEX idx_documents_created_at ON documents(created_at DESC);
CREATE INDEX idx_documents_current_version_id ON documents(current_version_id);
CREATE INDEX idx_documents_security_domain_gin ON documents USING GIN(security_domain);
CREATE INDEX idx_documents_tags_gin ON documents USING GIN(tags);
```

## 6.2 document_versions 表

用于记录文档版本。

```sql
CREATE TABLE document_versions (
    id UUID PRIMARY KEY,
    document_id UUID NOT NULL REFERENCES documents(id),
    version_no INTEGER NOT NULL,
    file_hash VARCHAR(128) NOT NULL,
    file_size BIGINT NOT NULL,
    mime_type VARCHAR(128) NOT NULL,
    storage_path TEXT NOT NULL,
    version_status VARCHAR(32) NOT NULL DEFAULT 'active',
    publish_date DATE NULL,
    effective_date DATE NULL,
    expire_date DATE NULL,
    change_summary TEXT NULL,
    created_at TIMESTAMP NOT NULL DEFAULT NOW(),
    updated_at TIMESTAMP NOT NULL DEFAULT NOW(),
    UNIQUE(document_id, version_no)
);
```

说明：

- `storage_path` 保存该 version 实际文件路径；
- `documents.storage_path` 保存逻辑文档主路径；
- `file_hash` 用于快速判断 replace 是否 unchanged；
- `file_size` 与 `mime_type` 用于文件校验、审计与调试；
- 允许同一 `document_id` 下存在多个历史版本。

`version_status` 枚举：

```text
active
expired
amended
draft
unknown
```

索引：

```sql
CREATE INDEX idx_document_versions_document_id ON document_versions(document_id);
CREATE INDEX idx_document_versions_version_status ON document_versions(version_status);
CREATE INDEX idx_document_versions_effective_date ON document_versions(effective_date);
CREATE INDEX idx_document_versions_publish_date ON document_versions(publish_date);
CREATE INDEX idx_document_versions_file_hash ON document_versions(file_hash);
```

## 6.3 chunks 表

用于记录 chunk 数据。

```sql
CREATE TABLE chunks (
    id UUID PRIMARY KEY,
    document_id UUID NOT NULL REFERENCES documents(id),
    version_id UUID NOT NULL REFERENCES document_versions(id),
    parent_chunk_id UUID NULL REFERENCES chunks(id),
    chunk_index INTEGER NOT NULL,
    chunk_type VARCHAR(32) NOT NULL,
    text TEXT NOT NULL,
    normalized_text TEXT NOT NULL,
    chunk_hash VARCHAR(128) NOT NULL,
    doc_type VARCHAR(64) NOT NULL,
    doc_title VARCHAR(512) NOT NULL,
    chapter VARCHAR(512) NULL,
    section VARCHAR(512) NULL,
    article_no VARCHAR(128) NULL,
    page_start INTEGER NULL,
    page_end INTEGER NULL,
    security_domain JSONB NOT NULL DEFAULT '[]',
    keywords JSONB NOT NULL DEFAULT '[]',
    metadata JSONB NOT NULL DEFAULT '{}',
    search_tsv TSVECTOR NULL,
    is_active BOOLEAN NOT NULL DEFAULT TRUE,
    created_at TIMESTAMP NOT NULL DEFAULT NOW(),
    updated_at TIMESTAMP NOT NULL DEFAULT NOW(),
    UNIQUE(version_id, chunk_index)
);
```

`chunk_type` 第一版固定枚举：

```text
parent
child
```

索引：

```sql
CREATE INDEX idx_chunks_document_id ON chunks(document_id);
CREATE INDEX idx_chunks_version_id ON chunks(version_id);
CREATE INDEX idx_chunks_doc_type ON chunks(doc_type);
CREATE INDEX idx_chunks_chunk_type ON chunks(chunk_type);
CREATE INDEX idx_chunks_is_active ON chunks(is_active);
CREATE INDEX idx_chunks_chunk_hash ON chunks(chunk_hash);
CREATE INDEX idx_chunks_parent_chunk_id ON chunks(parent_chunk_id);
CREATE INDEX idx_chunks_article_no ON chunks(article_no);
CREATE INDEX idx_chunks_page_start ON chunks(page_start);
CREATE INDEX idx_chunks_page_end ON chunks(page_end);
CREATE INDEX idx_chunks_metadata_gin ON chunks USING GIN(metadata);
CREATE INDEX idx_chunks_security_domain_gin ON chunks USING GIN(security_domain);
CREATE INDEX idx_chunks_keywords_gin ON chunks USING GIN(keywords);
CREATE INDEX idx_chunks_search_tsv ON chunks USING GIN(search_tsv);

## 10.4 Parent-Child Chunk 规则

必须实现 parent-child chunk。

规则：

```text

child 保存 parent_chunk_id

说明：

- parent 不参与向量检索；
- child 是唯一被索引的检索单元；
- 若某 child 没有 parent，则允许直接用该 child 参与答案生成，但这应是 fallback 方案，不是主路径。

## 11.3 替换文件流程

```text
用户上传新版本
  ↓
计算新 file_hash
  ↓
如果 file_hash 不变：返回 unchanged
  ↓
创建新 document_version
  ↓
创建 replace 类型 ingest_task
  ↓
解析新文件
  ↓
重新生成该 document 的新 chunks
  ↓
计算新 chunk_hash 集合
  ↓
读取该 document 当前版本 active chunks
  ↓
对比 old_chunk_hash_set 和 new_chunk_hash_set
  ↓
added：新增 chunk + embedding + index
  ↓
removed：旧 chunk is_active=false，同时停用检索可见性
  ↓
unchanged：复用旧 chunk，不重新 embedding
  ↓
updated：旧 chunk 失效，新 chunk 入库
  ↓
更新 document.current_version_id
  ↓
任务完成
```

核心要求：

- 只允许按 **chunk diff** 更新；
- 不允许因为替换文档而重建全库；
- 不允许对 unchanged chunk 重跑 embedding；
- unchanged chunk 的向量和检索数据必须复用。

伪代码：

```python
def update_document(document_id: str, new_file_path: str):
    new_file_hash = calc_file_hash(new_file_path)

    current_version = get_current_version(document_id)
    if current_version.file_hash == new_file_hash:
        return {"status": "unchanged"}

    parsed_doc = parser.parse(new_file_path)
    cleaned_doc = cleaner.clean(parsed_doc)
    new_chunks = chunk_service.chunk_document(cleaned_doc, doc_type=current_version.document.doc_type, base_metadata={})

    old_chunks = get_active_child_chunks(document_id=document_id, version_id=current_version.id)
    new_child_chunks = [c for c in new_chunks if c.chunk_type == "child"]

    old_map = {c.chunk_hash: c for c in old_chunks}
    new_map = {calc_chunk_hash(c): c for c in new_child_chunks}

    added_hashes = set(new_map.keys()) - set(old_map.keys())
    removed_hashes = set(old_map.keys()) - set(new_map.keys())
    unchanged_hashes = set(old_map.keys()) & set(new_map.keys())

    for h in removed_hashes:
        deactivate_chunk(old_map[h].id)
        deactivate_vector_point(old_map[h].id)
        deactivate_keyword_record(old_map[h].id)

    for h in added_hashes:
        save_new_chunk(new_map[h])
        embed_and_index(new_map[h])

    for h in unchanged_hashes:
        reuse_existing_chunk_index(old_map[h], new_map[h])

    create_new_document_version(...)
    update_current_version(...)
```

# 14. 检索模块

```text

## 14.1 检索流程

```text
1. 使用 rewritten_query 做向量检索；
2. 使用 rewritten_query + search_keywords 做关键词检索；
3. 两路结果用 RRF 融合；
4. 使用 reranker 对融合结果重排；
5. 返回 top_k evidence；
6. 对 evidence 回取 parent context。
```

## 14.2 固定参数

第一版默认参数：

- vector search top_k = 30
- keyword search top_k = 30
- RRF 输入候选 = 两路各 30
- reranker 输入候选 = 融合后前 20
- 最终 evidence top_k = 5

## 14.3 RRF 融合

```python
def reciprocal_rank_fusion(result_lists: list[list[SearchResult]], k: int = 60):
    scores = {}

    for results in result_lists:
        for rank, item in enumerate(results):
            chunk_id = item.chunk_id
            scores[chunk_id] = scores.get(chunk_id, 0) + 1 / (k + rank + 1)

    return sorted(scores.items(), key=lambda x: x[1], reverse=True)
```

## 14.4 Reranker 约束

第一版必须接入真实 reranker：

- 默认模型：本地 Qwen3 Reranker
- 调用方式：Python 进程内加载
- 仅对融合后的候选做重排，不参与初筛
