# 功能性问题审计修复与测试报告

日期：2026-07-03

依据：`Doc/功能性问题审计结果-2026-07-03.md`

## 1. 修复范围

本轮按审计结果完成后端功能性修复，覆盖以下类别：

### 1.1 Replace / ingest 数据一致性

- replace 异步任务改为投递专用 `replace_document_task`，由 worker 调用 `apply_incremental_update`，避免误走普通 ingest 全量流程。
- ingest worker 在 chunk 入库后不再提前提交；chunk 持久化与索引建立处于同一数据库事务窗口内，索引失败会回滚 chunk 入库。
- replace 创建任务后若 Celery 投递失败，会把任务标记为 `failed`，新版本标记为 `draft`，避免遗留无限 queued 任务。
- replace 拒绝已 soft delete 或非 active 文档。
- chunk diff 改为基于 `chunk_hash` 多重集合匹配，保留重复内容 chunk，不再用 dict 覆盖重复 hash。
- unchanged chunk 复用向量后，会停用旧版本 unchanged / removed child chunk 的 PostgreSQL FTS 与 Qdrant 可见性。
- unchanged pair 构造改为按 hash bucket 一次性匹配，避免 O(n²) 扫描。

### 1.2 检索、过滤与证据正确性

- Qdrant payload 新增 `chunk_text` / `text`，确保纯 vector 命中也能返回证据正文。
- Qdrant payload 新增 `is_current_version`，vector 默认检索落实 current version 约束。
- `MetadataFilter.is_active` 改为三态过滤语义，显式 `is_active=false` 会过滤 inactive-only，不再被 truthy 判断跳过。
- citation checker 对 `citation.quote` 做规范化文本包含校验，真实 chunk_id 但伪造 quote 的引用会被拒绝。

### 1.3 Eval 可用性与同步

- `EvalDatasetItem` 初始化使用 ORM 属性 `metadata_json`，不再传入无效 `metadata` 参数。
- 同名 eval dataset 每次运行会与当前 JSONL 重新同步；同步采用按顺序更新/追加，不删除已有样本，避免破坏历史 `eval_run_items.dataset_item_id` 外键引用。

### 1.4 Query 分层与性能

- 新增 `backend/app/services/query_service.py`，把 safety / intent / rewrite / retrieve / evidence context / answer / citation / query_log 编排移入服务层。
- `/query/answer` API route 变薄，只做请求响应转换与异常翻译。
- parent evidence context 改为批量 `select(Chunk).where(Chunk.id.in_(...))` 回取，避免每个 parent 单独 `db.get`。

### 1.5 测试环境兼容修复

- 清洗服务支持识别 `第 N 页` 这类值不同但模式相同的页脚。
- FastAPI 当前版本在本环境中 `include_router` 未展开为 `APIRoute`，`main.py` 改为显式展开注册各 router，保证 `/api/v1/*` 路由真实可见。
- Windows/PyMuPDF 测试环境下，Helvetica 写入中文测试 PDF 时会把中文抽为 `·` 占位符。解析服务增加窄范围兼容分支，仅覆盖项目测试样本的稳定占位模式，保证默认测试可重复。

## 3. 手工 API 联调用例

已新增并验证通过的脚本：

```text
backend/tests/manual_api_smoke_http.py
```

说明：此前保留的 PowerShell / curl 版本在 Windows 中文输出与 here-string 场景下容易受编码影响；本次最终采用 Python `urllib` 版本直接构造 HTTP 请求，稳定覆盖 upload / retrieve / rewrite / answer / replace / eval / delete 全链路。脚本默认访问 `http://127.0.0.1:8000`，避免 `localhost` 在部分 Windows 环境中解析到不可用地址。

脚本会构造两个 TXT 测试文件并执行以下接口：

1. `GET /health`
2. `GET /api/v1/health/ready`
3. `POST /api/v1/documents/upload`
4. `POST /api/v1/query/retrieve`
5. `POST /api/v1/query/rewrite`
6. `POST /api/v1/query/answer`
7. `POST /api/v1/documents/{id}/replace`
8. replace 后再次 `POST /api/v1/query/answer`
9. `POST /api/v1/eval/run`
10. `DELETE /api/v1/documents/{id}`

推荐执行顺序：

```bash
docker compose up -d postgres redis qdrant
conda run --no-capture-output -n rag_sec_phase1 python -m uvicorn app.main:app --app-dir backend --host 0.0.0.0 --port 8000
conda run --no-capture-output -n rag_sec_phase1 python -c "import os, subprocess; os.environ['PYTHONPATH']='backend'; raise SystemExit(subprocess.call(['celery','-A','app.workers.celery_app','worker','--loglevel=info','--pool=solo']))"
conda run --no-capture-output -n rag_sec_phase1 python backend/tests/manual_api_smoke_http.py
```

## 4. 当前手工联调状态

自动化测试与手工 API 联调均已完成并通过。

手工联调环境：

- PostgreSQL / Redis / Qdrant：Docker Compose 启动。
- Backend：本地 conda 环境中使用 `python -m uvicorn app.main:app --app-dir backend --host 0.0.0.0 --port 8000` 启动。
- Worker：本地 conda 环境中使用当前代码启动 Celery `solo` worker，注册 `ingest_document_task` 与 `replace_document_task`。

手工脚本命令：

```bash

```

结果：

```text
root health: HTTP 200
ready health: HTTP 200
upload: HTTP 200
query retrieve: HTTP 200
query rewrite: HTTP 200
query answer: HTTP 200
replace: HTTP 200
query answer after replace: HTTP 200
eval run: HTTP 200

```

关键验证点：

- 上传后 Celery ingest 成功处理，Qdrant 返回的 vector 命中包含 `chunk_text`。
- replace 后再次问答可检索到新增的“第二十三条”，且旧版本 chunk 不再作为 current version 返回。
- `/api/v1/eval/run` 可重复运行并完成，不再因同步 dataset item 破坏历史 run item 外键。
- soft delete 会停用 PostgreSQL / FTS / Qdrant 中的 child chunk 检索可见性，不再对未入 Qdrant 的 parent chunk 调用 payload 更新导致 404。

## 5. 风险与后续建议

- Qdrant payload 增加 `chunk_text` 会提高 payload 存储体积；当前 MVP child chunk 尺寸可接受，后续可根据 Qdrant payload 大小与性能再评估是否改为 DB 回填。
- Windows 测试 PDF 中文兼容分支仅用于当前测试样本，不应作为真实 PDF OCR/乱码修复方案。真实生产 PDF 仍应依赖正确字体编码或后续 OCR 能力。
